## Release milestones

1. **R0 — existing release:** retain/cite 0.2.0 and its exact public metadata.
2. **R1 — prepare:** freeze the 41-file inventory and link dictionaries/source
   receipts. Add remaining population selected graphs and reviewed original
   outputs only after they are actually prepared; enumerate omissions.
3. **R2 — review:** check source notices/attribution, private fields, creators,
   version metadata and exact software/manuscript snapshots. Original raw HPC
   packages stay untouched. Sanitized derivatives get new hashes and an
   omission/source mapping. Do not upload credentials, environment dumps,
   private full-text attachments, caches, container images or the Brazil PBF.
4. **R3 — new version:** publish a reviewed version related to 0.2.0 with README,
   units/column dictionary, asset-specific notices and SHA256 manifest. Preserve
   original and derivative identities. No blanket software licence is applied
   to upstream data. No new record/DOI/upload has been created by this plan.
5. **R4 — verify public bytes:** anonymously download the actual release,
   recalculate hashes, inspect archive members and verify links/dictionaries.
   Only then insert its new DOI/download URLs into the article and Appendix D/E.
6. **R5 — campaign results:** a later reviewed data version accounts for all 90
   configuration states and available original products, including censoring,
   failure and non-execution. No missing objective, gap or decision is imputed.
