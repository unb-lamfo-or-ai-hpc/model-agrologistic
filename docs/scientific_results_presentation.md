# Scientific results presentation protocol

## Purpose

This protocol transforms completed optimization runs into reader-facing tables,
figures, and tidy data suitable for an academic manuscript. It complements the
acceptance-oriented figures generated by `generate_scientific_plots.py`. The
acceptance figures diagnose whether the TRL 6 evidence package is internally
valid; the results figures explain what the model decided, how the network was
used, and how uncertainty changed the solution.

The presentation design follows the analytical sequence used in Artur's case
study: configuration summaries, cost composition, transport work, warehouse
operating profiles, inventory differences, deterministic-versus-stochastic
comparison, information metrics, and objective robustness. It does not claim
direct numerical replication where the data-generating process or network
instance differs from the thesis.

## Comparison domains

The generator keeps two evidence domains separate.

1. The full gold-workbook deterministic campaign compares direct
   origin-customer arcs and route-set reduction policies. Its valid factors are
   direct arcs enabled or disabled and Pareto or top-k route selection.
2. The adapted Artur instance compares the bounded deterministic baseline with
   controlled three- and nine-scenario stochastic extensions. These runs share
   the same transformed supply, demand, warehouse, and distance basis.

The thesis interhub factor, commonly denoted by alpha, multiplies interhub
transport cost. It is not a route-selection rule. A Pareto fraction or top-k
filter changes which arcs enter the model, whereas alpha changes the cost of
retained warehouse-to-warehouse arcs. Current results therefore report the
implemented direct-arc and route-filter factors explicitly and never relabel
them as alpha. An alpha sensitivity study requires a separate experiment
manifest and is outside this generator's evidence contract.

## Generation

Install the visualization stack and run the command from the repository root:

```bash
export PYTHONNOUSERSITE=1
python -m pip install -e '.[visualization]'
python scripts/generate_scientific_results.py
```

All source locations can be overridden:

```bash
python scripts/generate_scientific_results.py \
  --deterministic-policy-dir data/results/hpc/network_policy_sensitivity \
  --deterministic-baseline-dir data/results/hpc/artur_bounded_reproduction \
  --stochastic-extension-dir data/results/hpc/artur_stochastic_extension \
  --output-dir data/results/reproducibility/scientific_results_presentation \
  --dpi 300
```

Each figure is exported as PNG for review, vector PDF for publication, and CSV
for numerical traceability. Both summary tables are exported as CSV and
Markdown. `scientific_results_manifest.json` records source-result checksums,
units, interpretation scope, and generated-artifact checksums.

## Summary tables

`deterministic_configuration_summary` is the local counterpart of a
deterministic configuration table. It reports the direct-arc switch, route
filter and its parameter, economic and penalized objective values, disaggregated
economic costs, investment decisions, service, DynCap, turnover, emergency
capacity, model-size estimates, runtime, and peak memory.

`stochastic_configuration_summary` is reported by design and scenario, with an
additional probability-weighted expected row. Scenario objectives include the
common first-stage investment cost plus that scenario's operating and penalty
costs. The table also reports scenario probabilities, service, storage metrics,
emergency-capacity activation, EVPI, VSS, and first-stage decisions.

The same contents are exported as `deterministic_manuscript_table` and
`stochastic_manuscript_table`, with metrics in rows, reader-facing units, and
configurations or scenarios in columns. These transposed versions are intended
for direct adaptation into manuscript tables; the configuration summaries are
the machine-readable analytical sources.

## Figure set

The generator creates ten figure families.

1. `deterministic_cost_composition` shows 100% economic-cost composition across
   direct-arc and route-filter configurations. Big-M penalties are excluded from
   the percentage denominator and remain available in the summary table.
2. `deterministic_transport_work` reports billion tonne-kilometres by route type
   and product for every deterministic network-policy configuration.
3. `deterministic_warehouse_profiles` plots annualized DynCap against turnover.
   Color identifies investment status and bubble area represents outbound flow.
4. `direct_arc_inventory_difference` shows warehouse-period inventory changes
   between matched direct-enabled and direct-disabled runs for each route policy.
5. `deterministic_stochastic_cost_composition` compares the bounded
   deterministic baseline with the three- and nine-scenario stochastic designs.
6. `stochastic_transport_work` uses route-product heatmaps to expose physical
   network use across scenarios.
7. `stochastic_warehouse_profiles` adds scenario color and investment-status
   marker shape to the warehouse operating profile.
8. `stochastic_inventory_difference` compares the central stochastic scenario,
   or the probability-weighted inventory when no central scenario exists, with
   the bounded deterministic baseline.
9. `value_of_information_detailed` separates RP, WS, EV, and EEV objective
   values; EVPI; VSS; and the investment, operation, and Big-M penalty
   contributions to VSS.
10. `objective_robustness` reports the probability-weighted penalized objective,
    scenario minimum-maximum range, and EVPI. Scenario totals include the common
    first-stage investment cost.

Internal campaign gate identifiers are deliberately absent from reader-facing
labels. Figures use scientific concepts such as deterministic baseline,
three-scenario stochastic design, nine-scenario stochastic design, direct-arc
policy, and route policy.

## Units and interpretation

- Economic-cost and penalized-objective axes use billions of model monetary
  units. No currency symbol is asserted because Big-M penalties are
  feasibility devices rather than observed market costs.
- EVPI uses millions of model monetary units when this scale improves
  readability; VSS and objective values use billions.
- Transport work is calculated as transported tonnes multiplied by route
  distance and displayed in billion tonne-kilometres.
- Distance joins first require the exact exported node identifier. For legacy
  overlapping demand locations, the generator may resolve a typed domestic or
  export identifier to its physical city identifier only when the match is
  unique or all matching records report the same distance. The tidy transport
  data records the resolution mode, and ambiguous aliases stop generation.
- DynCap is annualized and displayed in tonnes per year or million tonnes per
  year, depending on the figure.
- Turnover is measured in inventory cycles per year.
- Inventory-difference heatmaps display thousand tonnes.
- Candidate and expansion capacity are static storage capacity. Bulkification
  capacity is a flow-rate decision and remains in tonnes per day.
- Emergency static capacity is aggregated in tonne-periods. Emergency reception
  capacity is aggregated in tonne-per-day-periods. They must not be added as if
  they were dimensionally identical physical capacity.

Domestic demand satisfaction and material balance are primary feasibility and
acceptance conditions. Emergency-capacity activation is retained as a strategic
capacity-gap diagnostic. It does not automatically invalidate an accepted
solution. Economic conclusions must therefore report modeled economic costs and
Big-M penalty contributions separately, especially when interpreting VSS.

## Manuscript use

The tables and figures reproduce the thesis's presentation logic, not its exact
numbering or numerical values. Captions should identify the evidence domain,
instance, scenario design, direct-arc setting, and route policy. Any later alpha
sensitivity result must be introduced as a distinct experimental factor. The
tidy CSV files are the authoritative values for manuscript tables and provide a
portable input for Quarto.
